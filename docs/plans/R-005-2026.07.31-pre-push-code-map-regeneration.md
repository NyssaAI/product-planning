# R-005 Pre-Push Code-Map Regeneration — Implementation Plan

Slice: R-005 — [F-203](../features/f-203/feature.md). Warn-only pre-push regeneration, shipped in the plugin for Claude Code and installable as a git hook everywhere else.

## Decisions

- The hook lives in the plugin (`hooks/hooks.json`), not in user settings; runtimes without hook support get a git pre-push hook via an install skill.
- Behavior is regenerate-and-warn: the push is never blocked, even on generator failure.
- Opt-out is `"prePushRegenerate": false` in `plan-product.config.json`, matching the existing `autoRegenerate` opt-out style.
- New plan documents follow `{R-NNN}-{yyyy.mm.dd}-{step-slug}.md`; this document is the first.

## Steps

- [x] Ship `hooks/hooks.json` with a PreToolUse hook on Bash that runs `pre-push-regen.mjs` via `${CLAUDE_PLUGIN_ROOT}`.
- [x] Write `scripts/module-map/pre-push-regen.mjs`: detect `git push` in the Bash command (stdin mode) or run unconditionally (`--git-hook` mode), regenerate synchronously, warn on uncommitted artifact changes, always exit 0.
- [x] Write `scripts/module-map/install-git-hook.mjs`: install a marker-delimited block into `.git/hooks/pre-push`, idempotent re-install, `--uninstall` removal, foreign content preserved.
- [x] Add the `install-code-map-hook` skill and `commands/install-code-map-hook.md` entry point.
- [x] Register the capability in README, CLAUDE.md, and AGENTS.md; add `hooks/` to the npm package files; bump all manifests to 2.2.0.
