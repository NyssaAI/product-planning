# UC-01.02.01 Define a Feature Guide Through Guided Interview

## Actor

A product owner or developer collaborating with a planning assistant to specify a product capability.

## Goal

Produce a complete, non-technical feature guide that defines who needs the capability, what it covers, what is outside its boundaries, and how completion is accepted—without overlapping or contradicting any other feature.

## Starting Context

- The project has an established feature catalog listing existing functional groups and features, and is ready for Stage 3 of [C-02: End-to-End Product Planning Lifecycle](../../concepts/c-02-product-planning-lifecycle.md).
- A starter layout for feature guides is available in the project.

## Entry Route

The user asks to plan or refine a specific feature (or invokes the feature-planning command).

## Trigger

The user names a new or existing capability they want to define or deepen.

## Process

```text
Actor defines a clear, non-overlapping feature guide
+-- Starting context: feature catalog and starter layout are available
+-- Entry route: user asks to plan or refine a feature
+-- Trigger: user names the target capability
+-- Step 1: identify the target feature or assign the next unused ID in the matching functional group (F-gg.nn)
+-- Step 2: interview the user one topic at a time for missing user need, scope, boundaries, inputs, outputs, and acceptance checks
|   \-- Decision: user skips or does not yet know a detail -> mark only the empty section as To be defined.
+-- Step 3: restate the proposed feature summary and boundaries (marking any inferred items) for user confirmation
+-- Step 4: compare the confirmed boundary against all other features in the catalog
|   \-- Failure path: overlapping ownership or contradiction found -> pause and resolve with the user by narrowing, splitting, or merging
+-- Step 5: save the feature guide and update the feature catalog summary and inventory
\-- Success: feature guide is saved and linked from the feature catalog with clear, non-overlapping boundaries
```

## Step Details

### Step 1: Identify or assign the feature ID

If the user names an existing feature, open its guide and preserve everything already written unless changes are requested. If the feature is new, choose the matching functional Feature Group (`gg`) and assign the next unused feature number (`nn`) without renumbering existing features.

### Step 4: Overlap and contradiction check

Compare the proposed capability scope against sibling feature guides. If two features claim responsibility for the same user outcome or state conflicting rules, stop and ask the user whether to narrow the boundary, merge the capabilities, or split them cleanly before saving.

## Success

A complete feature guide written in non-technical, user-focused language is saved in its feature folder, linked from the feature catalog's inventory section, and verified to have no overlapping ownership with other features.

## Failure Cases

- Missing starter template: restore the project's default feature layout before writing so the guide follows the expected structure.
- Overlapping or contradictory scope: pause before saving and resolve the boundary with the user by merging, splitting, or narrowing.
- Duplicate feature ID: select the next unused feature number inside the target functional group.

## Consistency Check

- Unique coverage: Covers defining capability-level boundaries for a single feature. Actor-level step-by-step process trees belong to use-case planning, and overall catalog setup belongs to product discovery.
- Closest related use cases: None yet.
- Contradictions: None found.
